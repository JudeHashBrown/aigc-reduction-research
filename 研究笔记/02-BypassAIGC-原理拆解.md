# 资料 02：BypassAIGC 原理拆解

代码：`/Users/wys/Documents/AI去重/BypassAIGC`（HEAD d9fab81）
核心文件：`package/backend/app/services/ai_service.py`、`optimization_service.py`

---

## 一句话原理

**它没有任何检测能力，是一个纯粹的「分段 + 两遍 LLM 改写」流水线；
真正的产品资产是那份中文 AI 腔黑名单提示词（版本号 `2026-08-28-humanizer`）。**

---

## 1. 处理链路

```
原文
 └─ split_text_into_segments(max_chars=500)
      先按 \n 切段；单段超 500 汉字则按 。!?; 再切
 └─ 逐段串行处理（不并行）
      段落 <15 字 → 判为标题，原样透传，不进上下文
      ├─ 阶段一 polish  （学术润色）
      └─ 阶段二 enhance （去痕增强，输入是 polish 的输出）
 └─ 每段完成后 sleep 6s（API_REQUEST_INTERVAL，防限流）
 └─ 历史累计汉字 >5000 → 调用压缩模型压成 30%
输出
```

四种模式：`paper_polish` / `paper_enhance` / `emotion_polish` / `paper_polish_enhance`（默认两遍）。

## 2. 提示词设计（真正的核心）

结构 = 角色定位 + 少量示例 + `_HUMANIZER_REWRITE_RULES` + `_ACADEMIC_OUTPUT_RULES`。

**去痕规则几乎全是负面清单**，中文 AI 腔黑名单分 20 类：
拔高（具有重要意义/深远影响）、热度空话（广受关注/引发热议）、假分析（通过…实现…/依托…推动…）、
宣传词（赋能/护航/全方位）、假权威（业内普遍认为/专家指出）、套话收尾（机遇与挑战并存/未来可期）、
黑话（闭环/抓手/底层逻辑/长期主义/颗粒度/范式/跃迁）、系动词回避（可视为/呈现出/彰显着 → 是）、
否定排比（不是…而是…/不只是…更是…）、三段空并列（更快、更稳、更智能）、
**同义词轮换**（平台/系统/工具/方案之间来回换）、假范围（从A到B/全生命周期）、
无主语（数据告诉我们/市场会奖励）、破折号、填充词（值得注意的是/总体而言）、
伪洞察（归根结底/本质上/核心在于）、开场导览、金句、伪口语钩子。

英文单独一段：禁 delve / leverage / robust / nuanced / pivotal / tapestry / landscape /
underscore / showcase；禁 `It's not X, it's Y`；禁 `serves as`/`stands as` 代替 is；禁 em dash。

**输出约束**：术语原样、逻辑一致、不用第一人称、保持段落划分、只输出正文、
中文只出中文、防提示词注入、**中文字数与原文相差不超过 30 字**（英文 ±10%）。

第二遍 enhance 的定位很明确：查第一遍的残留 ——「是不是每句差不多长；同一个意思是不是换了好几个词；
有没有『通过…实现…』这类空句；有没有展望或意义拔高」。

## 3. 工程细节

- **消息构造顺序反常**：`_build_paragraph_messages` 是 `history(全是 assistant) → system → user`。
  system 放在历史之后，且历史只有 assistant 没有配对的 user，是非常规的消息序列。
- **上下文只喂模型自己的输出**（不喂原文），目的是让后续段落风格一致。
- **压缩提示词要求「保留已经稳定的用词」**——刻意强化前后一致性。
- **thinking 模式默认开**：`reasoning_effort=high` 走 extra_body；与 temperature 互斥，
  即开思考时不传 temperature（走服务端默认）。失败时降级重试（去掉 reasoning，改用 temperature=0.7）。
- 过滤 `<think>`/`<thinking>` 标签，支持跨 chunk 检测。
- 默认非流式（`USE_STREAMING=False`，注释说流式易被 API 拦）。
- 伪装浏览器 User-Agent 调 API。
- 断点续跑：`failed_segment_index` 记录失败位置，重跑时只加载它之前的历史。

## 4. 业务层

卡密（card_key）+ 访问链接 + 使用次数限制；JWT 管理后台；Redis 信号量做并发上限
（`MAX_CONCURRENT_USERS`）+ 排队；SQLite 默认落在 exe 同目录，PyInstaller 打包三平台。
另有一个独立的 `word_formatter` 子系统（Word 排版：预处理 → AST → StyleSpec → 渲染 docx），
与去重无关，是捆绑的第二个功能。

## 5. 与资料 01（维基指南）对照

### ✅ 命中的
黑名单和维基指南的分类高度重合，说明是同一批现象被独立观察到：
拔高意义(AILEGACY) / 假分析 -ing 尾巴(SUPERFICIAL) / 模糊归因(AIWEASEL) / 否定排比(AIPARALLEL) /
三段式(RO3) / 系动词回避(AINOCOPULA) / 广告腔(AIPUFFERY) / 套话结尾(FACESCHALLENGES) /
em dash / 英文 AI 词表。

而且它**正确避开了维基指南列出的「无效指标」**：明确写了「不要为了显得高级换词」
「不要故意写错单词」「不要把短句拉长」。这一点比市面上多数降 AIGC 工具清醒。

两条维基指南没提、但它抓到的：
- **同义词轮换禁令** —— 对应维基的历史指标「lexical diversity / elegant variation」，抓得准
- **句长要有长有短** —— 对应检测器的 burstiness 维度，维基指南没写（因为那是给人看的）

### ❌ 缺的（这是我们的机会）

1. **没有恢复具体性的能力。** 维基指南判定的病根是「具体事实被抹成笼统褒扬」，
   而这套提示词明令「原文没有的不补」。学术诚信上正确，但也意味着它**只能做减法**：
   删掉浮夸，剩下干瘪。文本变短变平，但不会变得更像人写的。**这是该方案的天花板。**
2. **几乎没有正向的人类特征注入。** 维基指南 §Signs of human writing 给了五条可操作的目标
   （简单 is/has、朴素动词、敢下断言、对冲词 very/perhaps、啰嗦结构 in order to/the fact that），
   而这份提示词只有一条正向规则（「能用是就用是」），还有一条反着来
   （「不要为了显得完整而加的、地、所、会、可以、方面」——人类恰恰更啰嗦）。
   **95% 负面约束 = 纯粹的减法。**
3. **看不见文档结构。** 维基指南里最强的内容层信号是章节级的（「挑战与展望」章节、
   「获奖与荣誉」章节、僵硬的提纲结构）。但这套系统按 `\n` 切成 ≤500 字的段落独立处理，
   **结构性 AI 味在架构上就无法被发现**。
4. **完全没有度量。** 没有检测器、没有前后打分、没有验证回路。
   改完是否有效，全靠用户自己粘去第三方检测。因此**提示词无法被量化迭代**，
   只能靠作者手感改（看 git log 就是一路手改提示词）。
5. **不处理格式层**：加粗、要点列表、Title Case、弯引号、emoji、Markdown 残留全不管；
   而且按 `\n` 切分时结构信息已经丢了。

### ⚠️ 设计上的内在矛盾（值得警惕，别照抄）

- **自激风险**：上下文只喂模型自己的历史输出，压缩时还要求「保留已经稳定的用词」。
  这等于主动强化跨段一致性——而**一致性正是检测器度量的东西**。
  越往后写，句长分布越均匀、用词越收敛，可能反而更像 AI。
- **reasoning_effort=high 且不传 temperature** → 输出更收敛、更少变化。
  对「降 AI 率」这个目标来说，低方差方向可能是错的。
- **±30 字的长度约束很紧**，逼出近似同构的逐句改写，几乎无法做重组、拆并、语序重排——
  而重组恰恰是打散统计特征最有效的手段。
- **串行 + 6 秒间隔 + 两遍**：一万字的论文约 20+ 段 × 2 阶段 × (6s + 模型延迟)，
  实际要跑好几分钟到十几分钟。

## 6. 给我们项目的结论

可以继承：黑名单词表（直接能用，是现成的中文语料资产）、两遍流水线的思路、
断点续跑 / 并发控制 / 卡密这些工程外壳。

必须做得不一样的三件事：

1. **加度量**：先做可解释的检测打分器（资料 01 第 8 节的规则打分器），
   让改写有目标函数，能量化迭代，也能直接当产品卖点（「告诉你哪句像 AI、为什么」）。
2. **加正向注入**：不只删 AI 味，还要按 §Signs of human writing 注入人类特征。
   减法有天花板，加法才有空间。
3. **加结构视野**：先做全文级的结构分析（章节套路、段落长度分布、句长分布），
   再下沉到段落改写。不能只在 500 字窗口里打转。

另外要想清楚一个产品定位问题：**「降 AI 率」和「说人话」不完全是一回事。**
纯粹对抗检测器是军备竞赛，检测器一升级就失效；
而「恢复具体性、让文章真的好读」是能长期站住的。资料 01 的病根分析支持后者。
