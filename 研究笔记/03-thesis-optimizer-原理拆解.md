## 一句话原理

**它是一套让 Claude 按流程改论文的「作业指导书」：两层文档（总揽 + 章节）+ 状态追踪，
把长论文拆成可断点续跑的章节任务，靠 6 份参考文档约束改写行为。**
与 BypassAIGC 正好互补：那边是有代码没方法论，这边是有方法论没代码。

## 1. 工作流

```
Phase 0   读全文 → 生成 thesis_master_overview.md（章节矩阵 + 进度条）
Phase 0.5 全文 AI 模式扫描 → 按 6 大类 30+ 种模式生成「检出热力图」
Phase 1   逐章循环：建 chapter_XX.md → 应用策略 A-F → 出 LaTeX → 更新总揽 → 评分
Phase 2   汇总评估 → 标记 🔴需返工 → 回 Phase 1
```

状态标记：⏳待处理 / 🟡进行中 / 🟢已完成 / 🔴需返工 / ⭐已验证。
显式的「防偏移设计」：每章文档头部链回总揽，每次更新打时间戳。

## 3. 独有贡献（BypassAIGC 和维基指南都没有的）

1. **结构模式 S02「完美的逻辑闭环」** —— AI 叙述没有转折、意外、失败尝试，
   直线型 问题X→方法Y→结论Z，不符合人类科研的曲折性。**这是段落/章节级的信号，
   是本资料最有价值的一条。**
2. **语气模式 T01「无人称上帝视角」** —— 建议适度使用「本文/本研究」表达研究意图。
   与维基指南「人类敢下断言」同源。
3. **正向注入的意识** —— 技术2「学术语气自然化」明确要求加作者视角和主观判断，
   补上了 BypassAIGC「只做减法」的缺口。
4. **全文级视野** —— 两层文档架构正好补 BypassAIGC 的结构盲区。
5. **句长标准差 > 8** —— 一个可计算的量化参考（虽是经验值，无出处）。
6. **术语保护白名单** —— 公式/变量、专业缩写、参考文献显式绕过；
   明确写「不要为了降重把 Transformer 改成变换器模型」。
7. **风险等级 🔴🟡🟢** —— 可直接当检测器的规则权重。
8. **区分了「降 AI」和「降查重」两个独立目标**（虽然没处理好两者的冲突）。

## 4. 严重问题

### 4.1 文档自相矛盾（有 git 证据）

SKILL.md 三令五申「最小干预、句内微调、不要大段扩写」，
但 `strategy_ai_reduction.md` 技术1/2/3 的示例全是**大幅扩写**——
摘要案例把 3 句约 70 字扩成 200+ 字，完全是另一套做法。

git 证明了这是补丁式修改：commit `4fa0646`（"enforce minimal intervention principle"）
**只改了 README.md 和 SKILL.md，没动 references/ 里的示例**。
顶层原则换了，底层示例还是老的。模型执行时会以更具体的示例为准 → 原则形同虚设。

### 4.2 教人编造研究过程 ⚠️ 学术不端风险

技术2.3「保留学术探索的自然推进」的推荐写法：
> ✅ "初步实验中，我们尝试了...方法，但发现其在...场景下性能受限。
>    经过深入分析，我们意识到问题的根源在于...。基于这一洞察，我们进一步提出了改进方案..."

**如果作者根本没做过这些初步实验，这就是伪造研究过程。**
BypassAIGC 的「原文没有的日期、数字、来源、因果、评价，不补」在这点上明显更正确。
S02 的诊断是对的（AI 叙述太顺），但开的药方越界了。
正确做法应该是：**提示作者补充他真实经历过的曲折**，而不是让模型编。

### 4.3 降查重策略与降 AI 策略直接打架

`strategy_plagiarism.md` 给了一张同义替换表（提出→设计/构建/开发，有效→高效/显著/优异，
方法→策略/机制/框架），而：
- `perplexity_burstiness.md` 明确警告这是**「换词陷阱」**：「只替换少量词语却保留原句法，
  读起来像机器改写，也不一定降低任何检测器分数」
- 分类学 L05 把**「同义词机械循环」**列为 🟡 风险模式

**一边禁同义词轮换，一边给同义词轮换表。** 且最新 commit 没有修 `strategy_plagiarism.md`
（它自初始提交起就没动过）。

### 4.4 没有实现

全靠 Claude 读文档自觉执行。句长标准差要模型自己算（不可靠），
模式扫描靠模型自觉对照，无任何自动化。等于把方法论写下来，执行质量全看模型当天状态。

### 4.5 量化指标无出处 + 前后不一

句长标准差>8、AI率<10%为⭐优秀、查重<10% —— 均无验证来源。
且 `evaluation_criteria.md` 保留硬阈值表，SKILL.md 却说「不承诺固定阈值」「检测器结果仅作参考」。
大量对冲免责话术明显是后期加的（怕担责），代价是**指令强度被稀释**，模型执行时会犹豫。

## 6. 对我们项目的结论

**可以直接拿来用的：**
- 6 大类分类学 + 风险等级 → 现成的检测器规则骨架和权重
- 结构模式 S01-S05、语气模式 T01-T04 → 补 BypassAIGC 的结构盲区
- 术语保护白名单机制 → 必须实现（不能只写在提示词里）
- 两层文档 + 状态追踪 → 长文档分章处理的工程骨架，可复用
- 「删掉段首 4 个字」这类可自动化的启发式规则

**必须避开的坑：**
1. **不要教模型编造研究过程。** 诊断 S02 是对的，但药方应该是标注出来让作者自己补真实经历，
   而不是生成。这条是学术诚信红线，也是产品的法律风险线。
2. **降 AI 和降查重必须显式分离建模。** 两者策略天然冲突（降查重要换词、降 AI 要少换词），
   混在一起必然自相矛盾。应该让用户选目标，或者做成两条独立通道 + 冲突仲裁。
3. **原则和示例必须同步更新。** 模型永远以具体示例为准，不是以顶层原则为准。
4. **文档型方案没有度量就无法迭代。** 这是它和 BypassAIGC 的共同死穴。

**三份资料合起来指向同一个产品形态：**
```
全文结构分析（thesis-opt 的视野）
  → 可解释规则打分（维基分类 + thesis-opt 风险等级）
  → 分段改写（BypassAIGC 的工程外壳 + 黑名单）
  → 正向人类特征注入（维基 §Signs of human writing）
  → 重新打分验证 → 未达标回炉（谁都没有的闭环）
```
