# 朱雀实测：LLM 改写无法降低 AI 率

2026-09-22，腾讯朱雀（matrix.tencent.com/ai-detect/）。

## 结果

| 文本 | 改动幅度 | 朱雀判定 |
|---|---|---|
| 真人写的学术段落 | — | **0%** |
| b11 AI 原版 | — | 100% |
| b11 全清（规则层消除全部已知 AI 特征） | 改 18 字（3%） | **100%** |
| b11 两层改写（本项目，白名单约束） | 改 3 字（1%） | **100%** |
| b11 激进改写（不加约束让模型「降 AI 率」） | 改 318 字（**59%**） | **100%** |
| b17 另一篇 AI 原版 | — | 100% |

## 两条结论

**一、朱雀的分辨力极好，不是天花板效应。**
真人 0%、AI 100%，中间没有含糊。最初怀疑「两边都 100 是因为标尺顶满」，
量程校验直接否掉了这个解释——尺子非常准，是我们推不动它。

**二、用 LLM 改写降不了 AI 率，改多狠都一样。**
激进改写动了 59% 的字，分数纹丝不动。这坐实了本项目开篇就写下、
但一直没能验证的那个判断：

> LLM 改写会重新从高概率区采样，把 AI 统计特征再注入回去。

**LLM 生成的文本，不可能靠另一个 LLM 洗白。** 换词、改句式、调语序，
都还在同一个分布里。朱雀看的是整篇的 token 概率分布，不是破折号和顿号。

## 对产品的意义

这一条同时否掉了三样东西：

1. **本项目的规则层**——全清（3% 改动）无效
2. **本项目的改写层**——白名单约束下只改 1%，无效
3. **整个竞品品类**——R4 就是所有「降 AI 率」工具和 ChatGPT 的通行做法，
   同样无效。它们要么在骗人，要么用的是我们还不知道的别的手段

## 尚未排除的可能

- **知网/维普可能不同**。朱雀是免费代理靶，中国高校真正的守门人是知网（约 60%）
  和维普（约 25%），训练语料与判别逻辑都不一样，必须单独验证。
- **真人手改可能有效**。R1 证明真人写的文本能拿 0%。但「真人改 AI 文本」
  需要多大改动量才越过边界，未测。
- **非 LLM 的变换未测**：回译、人工信息注入等不经过 LLM 采样的路径。

## 方法学记录

本次实验有一个我无法解决的confound：**我自己就是 LLM**，
任何由我生成的「像人写的」样本仍然是 LLM 输出。
真正的人类对照只能由用户本人提供。

# 补充：humanizer-zh-academic 的可执行性检验

2026-09-28。让三个独立的模型分别「严格按照它的 SKILL」改写同一篇 b11_材料，
再让另外三个独立的模型逐条核查是否忠实执行。**三份改写全部核查不通过。**

## 三个共同失败点

**一、它唯一真正需要发力的那条硬约束，三份都没修好。**

原文 538 字，对照它的七条硬约束，**只违反其中一条**——「整齐三元并列每段 ≤1 处」。
其余六条原文本来就达标。而三份改写全部在这一条上仍然超限：

| 版本 | 改写后仍超限的段落 |
|---|---|
| H1 完整版 | P2=1、P3=2、P4=2 |
| H2 精简版 | P1=3、P2=2、P5=2 |
| H3 禁新增 | P1=2、P2=2 |

核查员的原话：「改写在唯一需要它发力的地方没做到位。」
原文 8 处三项以上并列，真正被打破的只有 2 处，其余多是只换了连接词。

**二、大量未申报的编造，而且集中在技术事实一侧。**

H3 那一版被明确要求「绝对不许新增」，自报新增 0 处。核查员逐句比对后找出
**15 处未报告的新增**，其中包括实打实的事实编造：

- 「石墨烯表面并不平整」——原文只说存在缺陷、边缘位点及含氧官能团，
  **从未对表面形貌作任何描述**。这是新增的物理表征。
- 「批次一致性」——原文是「规模化一致性不足」，「批次」二字原文没有。

H2 自报 8 处，核查员另找出 9 处未申报，并指出一个规律：
**申报的都是明显的风格性发挥，漏报的系统性地落在材料学实质主张一侧。**

**三、文本大幅膨胀。** 原文 497 汉字 → 改写 721~794 字，扩写 45%~60%。
扩出来的几乎全是原文没有的作者议论与判断。

## 这说明什么

1. **它不可被忠实执行。** 不是执行者不用心——三个独立执行、三个独立核查，
   结论一致。19 处数值阈值全靠模型目测自估，没有任何测量装置，
   落到实处就是「看起来改了改」。
2. **「不新增事实」这条约束在 LLM 改写里守不住。** 即使写成最高优先级的
   硬性限制、即使要求逐项申报，模型仍会在技术细节上产生它自己都察觉不到的编造。
   本项目 engine/guard.py 那种机械比对不是洁癖，是唯一能兜住这类问题的手段
   ——而它也只兜得住数字、专名、引用和实义术语，兜不住「并不平整」这种
   形容词级的事实增生。
3. **它的自评机制会给出 49/60「良好」。** H1 自评里「抗检测性 8/10」，
   而外部核查的结论是「忠实=False」。这正是「抗检测性」这个维度
   结构上不可证伪的直接演示。

# 补充二：第一个不是 100 的分数

2026-09-28，同一把尺子（朱雀），同一篇 b11_材料。

| 文本 | 改动 | 执笔 | 朱雀 |
|---|---|---|---|
| b11 原版 | — | gpt | 100 |
| b11 全清（规则层） | 3% | 代码 | 100 |
| b11 两层改写（本项目） | 1% | gpt | 100 |
| b11 激进改写（R4，行业通行做法） | 59% | gpt | 100 |
| **H1 忠实执行 humanizer 完整版** | **111%** | **Claude** | **0** |
| **H2 忠实执行 humanizer 精简版** | **108%** | **Claude** | **32.25** |

在这之前，这个项目**所有**测量都是 100。

## 这个 0 暂时不能采信

H1 相对基准同时变了三件事，不是一件：

1. **执笔模型换了**。基准、R2、R4 都是 gpt-5.6-sol；H1/H2/H3 是
   Claude（工作流子代理）。朱雀对不同来源模型的识别率未必相同。
2. **长度变了**。794 字 vs 538 字，长 47%。
3. **内容变了**。改动 111%，且核查确认包含原文没有的事实
   （见上一节，H3 有 15 处未申报新增）。

三者都能单独解释 0 分，而第 1 条的产品含义与第 3 条**完全相反**：
如果只是「换个模型执笔」，那这套 SKILL 一文不值，产品是一行 API 配置；
如果是改写方式起作用，那 SKILL 有价值但伴随编造，需要另建守卫。

## 四条对照

| | 隔离的变量 | 判读 |
|---|---|---|
| C0_原版重测 | 检测器本身 6 天内的漂移 | 不是 100 → 所有历史分数不可比 |
| C1_朴素改写_Claude写 | **执笔模型**（对照 R4：同样激进、同样长度、同样无约束，只换执笔） | 也接近 0 → H1 的 0 与 SKILL 无关 |
| C2_H1截到原版长度 | 长度 | 回到 100 → 0 分是长度效应 |
| C3_真人文本经gpt改写 | 反向：真人文本过一遍模型 | 0 → 100 说明模型改写会把人写的打成 AI |

C1 是关键的一条。
