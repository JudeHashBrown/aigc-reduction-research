# 第一部分：原理

## 1. 先分清两件事——这是全部设计的前提

用户说的"降重"在中文语境里其实是**两个完全不同的目标**，检测原理不同，
**且策略互相冲突**。三份资料里没有一份把这件事处理干净，thesis-optimizer 因此自相矛盾。

| | 降查重率 | 降 AI 率 |
|---|---|---|
| 检测方 | 知网 / 维普 / 万方 | GPTZero / Turnitin AI / 朱雀 / 各校自建 |
| 原理 | **字面比对**：分词后做 n-gram / 短语级匹配，与已收录文献库比对 | **统计分类**：困惑度、句长分布、词汇分布、文体特征喂分类器 |
| 判定对象 | 你的文字**和别人的**是否雷同 | 你的文字**和 AI 的**统计特征是否相似 |
| 有效手段 | 改变表层字面：换词、换语序、换句式 | 改变统计分布：打散规律、增加信息密度 |
| **冲突** | 换词换句 → 制造"机器改写感" → **AI 率上升** | 少换词保自然 → 字面不变 → **查重率不降** |

**结论：必须做成两条独立通道 + 冲突仲裁，让用户选主目标。**
不能像 thesis-optimizer 那样一边给同义词替换表、一边禁同义词轮换。

真实场景下的优先级：多数学校现在**AI 率卡得比查重严**（查重有成熟规则，AI 率是新增关卡），
所以默认主目标建议设为降 AI 率，查重作为次目标。

## 2. AI 率的病根：回归均值

维基指南给出的机制解释（也是三份资料里唯一讲到根因的）：

> LLM 输出趋向统计上最可能、适用面最广的表达，于是把**罕见的具体事实**
> 抹成**常见的笼统褒扬**。结果是文本同时变得**更不具体**和**更夸张**。

推论（这是整个产品的理论基点）：

- **换同义词不解决问题**——夸张和笼统还在，统计分布还在
- **删掉浮夸只解决一半**——变得不夸张了，但更干瘪，具体性没回来（BypassAIGC 的天花板）
- **真正的解法是恢复具体性**——把数字、条件、机制、限定塞回去
- **但 AI 不能编造事实**——所以恢复具体性**必须做成人机交互**，不能纯自动

**最后这条推论就是产品的护城河**：竞品都在做纯自动改写，天花板锁死在"删浮夸"。
只要引入"标出空泛处 → 让作者补真实细节"的交互，就跨过了那个天花板，
而且这条路竞品抄不走（他们的形态是一键改写）。

## 3. 检测器实际在测什么（三方交叉验证）

| 层 | 可测特征 | 三方是否共识 |
|---|---|---|
| **词汇层** | AI 高频词密度、词汇丰富度、同义词轮换 | ✅ 三方 |
| **句法层** | 句长标准差（burstiness）、句式模板重复率 | ✅ 两方（BypassAIGC + thesis-opt） |
| **语义层** | 信息密度低、空泛评价多、具体名词/数字稀疏 | ✅ 三方 |
| **结构层** | 段落模板化、编号排比、逻辑闭环完美无转折 | ⚠️ 仅 thesis-opt（但很重要） |
| **文体层** | 拔高意义、模糊归因、否定排比、三段式、-ing 尾巴 | ✅ 三方 |
| **格式层** | 破折号、粗体、要点列表、弯引号、emoji | ✅ 两方 |

### 三方独立命中的 12 个特征（可靠工程依据，直接进规则表）
拔高意义 · 模糊归因 · 提纲式挑战与展望 · 广告宣传语 · 句尾浮泛分析 ·
回避系动词 · 否定式排比 · 三段并列 · 同义词机械轮换 · 填充词 · 破折号 · 粗体列表

### 三方一致反对的做法（写进硬约束）
❌ 故意制造语法错误 ❌ 口语化 ❌ 为显得高级换生僻词 ❌ 把短句拉长凑字数

### 正向目标：人类写作特征（维基基于 25 年语料的统计）
1. 简单的"是/有"结构
2. 朴素动词（写 而非 撰写；用 而非 运用；试 而非 尝试）
3. 敢下断言（"是唯一的""首次"）
4. 对冲词和程度词（很、也许、大致）
5. 适度啰嗦（"为了……""的原因在于……"）
6. 作者视角（"本文""本研究"）
7. 逻辑有曲折（真实的失败尝试、条件限制）← 必须由作者提供，不可生成

# 第二部分：架构

## 4. 五层流水线

```
┌─ ① 解析层 ─────────────────────────────────────────┐
│  docx / LaTeX / PDF / 纯文本                        │
│  → 文档树：章 → 节 → 段 → 句（保留结构，不丢！）      │
│  → 术语白名单抽取：公式、英文缩写、数据集名、           │
│     指标名、参考文献、代码标识符                       │
└────────────────────────────────────────────────────┘
                      ↓
┌─ ② 诊断层（差异化核心，三家都没有）──────────────────┐
│  A 规则引擎：分级词表匹配 + 句式正则 + 结构模式         │
│  B 统计引擎：句长标准差/分布、n-gram 自相似度、          │
│              标点分布、实词密度、数字密度               │
│  C 语义引擎：LLM 判空泛度 / 具体性 / 逻辑曲折度         │
│  → 全文热力图 + 逐句归因 + 加权总分                    │
└────────────────────────────────────────────────────┘
                      ↓
┌─ ③ 交互层（护城河）────────────────────────────────┐
│  把"空泛但不能自动补"的句子挑出来，问作者：             │
│  "这里说'效果显著'——具体提升了多少？在什么条件下？"      │
│  作者填真实信息 → 进入改写上下文                       │
│  （作者不填也能继续，只是效果打折）                     │
└────────────────────────────────────────────────────┘
                      ↓
┌─ ④ 改写层（按有效性排序的分层动作）────────────────┐
│  1. 具体化：用作者提供的真实信息替换空泛评价            │
│  2. 减法：删 -ing 浮泛尾巴、意义拔高、套话段落          │
│  3. 句法：还原系动词、拆否定排比、破三段式              │
│  4. 词汇：只收敛词表内的 AI 高频词（不动其同义词）       │
│  5. 节奏：拆长句 / 合碎句，调句长方差                   │
│  6. 结构：打散编号排比、融合生硬路标过渡                │
│  7. 正向注入：作者视角、朴素动词、适度啰嗦              │
│  ※ 术语白名单全程 mask 保护                           │
└────────────────────────────────────────────────────┘
                      ↓
┌─ ⑤ 验证闭环（三家都没有）──────────────────────────┐
│  改写后重新跑②打分 → 未达标段落回炉（限 N 轮）          │
│  + 语义保真校验：改写前后事实/数字/逻辑是否一致          │
│  → 出对照报告（改了什么、为什么改）                     │
└────────────────────────────────────────────────────┘
```

## 5. 关键工程决策（都是从前人踩的坑推出来的）

| 决策点 | 前人做法 | 我们的做法 | 理由 |
|---|---|---|---|
| 分段 | BypassAIGC 按 `\n` 切 500 字 | 保留完整文档树 | 否则结构层 AI 味在架构上就发现不了 |
| 上下文 | 只喂模型自己的历史输出 | 喂原文上下文 + 术语表 + 作者补充信息 | 前者有**自激风险**：模型强化自己的 AI 腔，越写越像 AI |
| 一致性 | 压缩时"保留已稳定用词" | 反过来，**主动引入变化** | 一致性正是检测器度量的东西 |
| 采样 | reasoning=high 且不传 temperature | 适度提高多样性 | 低方差方向对降 AI 是反的 |
| 长度约束 | ±30 字硬约束 | 段落级 ±15%，句级不限 | 硬约束会阻止重组，而重组最有效 |
| 术语保护 | 只在提示词里说"保持原样" | 显式抽取 + mask + 还原 | 提示词约束不可靠 |
| 度量 | 无 | 全流程打分 + 闭环 | 没度量就无法迭代，只能靠手感 |
| 目标冲突 | 混在一起 | 降 AI / 降查重两条通道 + 用户选主目标 | 两者策略天然冲突 |

## 6. 红线（产品 + 法律）

1. **绝不编造事实、数据、实验过程。** thesis-optimizer 教模型写
   "初步实验中我们尝试了…但发现…"——作者没做过就是学术不端。
   我们的做法：**标出来问作者**，而不是替他编。
2. **不承诺具体检测率数字。** 各检测器差异大且会升级，承诺"降到 10% 以下"
   既做不到也是虚假宣传。只承诺"降低风险特征 + 给出可解释报告"。
3. **定位为写作质量提升，不是对抗检测。** 这既是合规需要，也是长期正确的方向：
   纯对抗检测器是军备竞赛，检测器一升级就失效；
   "恢复具体性、让文章真的好读"能长期站住。

# 第三部分：落地

## 7. 差异化与商业设计

**免费引流**：诊断报告。上传文档 → 免费看全文热力图和逐句归因
（"这句为什么像 AI"）。这是三家竞品都做不到的，天然的传播点。

**付费转化**：一键改写 + 交互式具体化 + 导出对照报告（保留原格式）。

**护城河**：交互式补真实信息。竞品的形态是"一键改写"，无法引入作者知识，
天花板锁死在"删浮夸"。我们跨过那条线。

**技术栈建议**（沿用 BypassAIGC 已验证的部分）：
- 后端 FastAPI（诊断引擎用 Python 现成的中文 NLP 生态：jieba/HanLP + numpy）
- 前端 React + Vite（热力图和逐句归因是重前端交互）
- LLM 走 OpenAI 兼容接口，多模型可配（诊断用便宜快的，改写用强的）
- 任务队列 + 断点续跑 + 并发限流（照抄 BypassAIGC 的工程外壳）
- 存 PostgreSQL（要存诊断结果做迭代分析，SQLite 不够）

## 8. 建议的实施顺序

1. **先做诊断引擎**（规则 + 统计两层，不含 LLM）——最快能出可演示的东西，
   而且它是改写的目标函数，没它后面全是盲改
2. 再做改写层的减法动作（2-6），用诊断打分验证效果
3. 再做交互式具体化（护城河，但需要产品设计打磨）
4. 最后做验证闭环和多轮迭代
5. 降查重通道单独做，别和降 AI 混
