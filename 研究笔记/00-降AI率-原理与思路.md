# 降 AI 率 · 原理与思路

目标锁定：**只做降 AI 率**，不做降查重。
（查重是字面比对，策略与降 AI 冲突，另开通道或不做）

---

# 一、检测器到底怎么工作

必须先搞清楚敌人是什么，否则所有优化都是盲改。AI 文本检测有三条技术路线：

## 1. 困惑度类（perplexity-based）
代表：早期 GPTZero、DetectGPT

拿一个代理语言模型跑你的文本，算每个 token 的对数似然。
- **AI 文本 = 低困惑度**：因为它本来就是从语言模型的高概率区采样出来的，
  另一个语言模型看它会觉得"这太好猜了"
- **人类文本 = 高困惑度 + 高 burstiness**：人会突然用一个怪词、一个长句、
  一个不那么顺的转折，困惑度在句子之间起伏很大

DetectGPT 的变体更狠：AI 文本处在模型对数概率曲面的**局部极大值**上，
对它做微扰，似然会掉得比人类文本更明显。

## 2. 监督分类器（supervised classifier）—— 中文场景的主力
代表：知网 AIGC 检测、万方、腾讯朱雀、各校自建

拿 BERT/RoBERTa 类模型，在"人写 vs AI 写"的语料上微调，直接二分类。
- 它学到的不只是困惑度，更是**表层文体特征**：用词偏好、句式模板、
  段落结构、标点习惯
- **这就是为什么词表和句式黑名单有效**——分类器确实学到了这些标记
- 弱点：只能检测训练时见过的分布。新模型、新文体、跨领域都会掉点

## 3. 特征工程 / 混合
句长分布、词性 n-gram 分布、虚词比例、类符形符比（TTR）、
依存句法树深度方差、标点分布……喂给传统分类器或和上面两类做集成。

> **判断：中文学术场景以第 2 类为主，第 1、3 类为辅。**
> 这决定了我们的策略权重——针对表层文体特征的处理**立竿见影**，
> 但也**最容易失效**（对方重新训练即可）。

# 二、AI 文本为什么会被测出来

一句话：**AI 文本处在文本空间里一个低熵、高一致性的狭窄区域。**

机制拆开看：

| 成因 | 后果 |
|---|---|
| 自回归采样 + temperature<1 | 系统性偏向高概率 token → 困惑度低 |
| RLHF 对齐（要"有帮助、全面、平衡"） | 套话、对仗、面面俱到、过度铺垫 |
| 训练语料的均值效应 | 具体罕见事实 → 笼统常见褒扬（维基的"回归均值"） |
| 单次生成、无真实认知过程 | 逻辑直线闭环，没有失败尝试和真实曲折 |

**关键推论：具体的事实是低概率 token。**
"提升了 2.3 个百分点，在缺失率 40% 的条件下"——这些词对代理模型来说难猜，
困惑度天然就高。而"显著提升了性能"每个词都好猜。

> 所以 **"恢复具体性"和"提高困惑度"是同一件事的两个说法。**
> 这也意味着：**"说人话"和"降 AI 率"在这个杠杆上是完全统一的，不冲突。**
> 这是整套方案的理论基石。

# 三、三个杠杆，按鲁棒性排序

## 杠杆 1：信息注入 —— 最有效、最鲁棒 ⭐
往文本里加**真实的具体信息**：数字、条件、机制名、限定、反例、边界。

- 天然提高困惑度（具体词是低概率词）
- 天然提高信息密度（分类器学到的"空泛度"特征下降）
- **唯一一个「提高指标的同时文本真的变好」的杠杆**，其他都是取舍
- **检测器无法通过重新训练来对抗**——因为真实的、作者提供的具体内容
  本来就是人类内容

代价：信息必须来自作者，不能生成。→ 必须做成人机交互。
**这是护城河，也是竞品做不到的地方**（他们是一键改写形态）。

## 杠杆 2：分布打散 —— 中等有效、中等鲁棒
提高各种统计量的方差：句长、句式结构、段落长度、标点使用。

- 直接打击 burstiness 和句法均匀度特征
- 大部分可以**用代码做**，不需要 LLM（见第四节）
- 注意：要靠真实的内容重组产生变化，不要机械地凑长短句

## 杠杆 3：特征消除 —— 立竿见影、最不鲁棒
删掉分类器学到的表层标记：AI 高频词、否定排比、三段式、-ing 尾巴、
拔高套话、破折号、粗体列表。

- 对当前的中文检测器**效果最直接**
- 但这是**跑步机**：对方重新训练就失效
- 成本最低，应该做，但不能只做这个

> **市面上所有产品都只做杠杆 3。这就是它们的天花板，也是我们的机会。**

# 四、根本悖论：用 LLM 改写会重新注入 AI 特征

**你用 LLM 改写，就是又从语言模型的高概率区采样了一次。**
改完的文本可能换了一批词，但统计特征还是 AI 的。这是所有 LLM humanizer 的死结。

BypassAIGC 把这个问题放大了：它的上下文只喂模型自己的历史输出，
压缩时还要求"保留已稳定的用词"——等于**自激**，越写越收敛，越写越像 AI。

## 解法：能用代码做的绝不用模型做

这是我们和三个前人方案最大的架构差异——**它们 100% 靠提示词，我们代码优先**。

| 操作 | 用什么做 | 为什么 |
|---|---|---|
| 词表替换（AI 高频词 → 平实词） | **代码**（查表 + 上下文规则） | 确定性，不引入 LLM 统计 |
| 删填充词、删段首套话 | **代码**（正则 + 句法） | 删除操作不会加入新 token |
| 拆长句 / 合碎句 | **代码**（标点 + 句法边界） | 纯结构操作 |
| 破折号、粗体、要点列表 → 正文 | **代码** | 格式层，纯规则 |
| 编号排比 → 递进叙述 | LLM | 需要理解语义 |
| 空泛评价 → 具体表述 | LLM + **作者提供的信息** | 信息来自人，不是模型 |
| 逻辑曲折补充 | **只能作者写** | 红线：不许编 |

四条配套原则：

1. **约束 LLM 只做删除和重组**，尽量不做自由生成——删除不会引入 AI token
2. **LLM 之后必须再跑一遍代码后处理**，让最后碰文本的是确定性代码
3. **不要喂模型自己的输出做上下文**，要喂原文 + 术语表 + 作者补充
4. **LLM 环节适度提高采样多样性**，不要像 BypassAIGC 那样 reasoning=high 配低方差

# 五、目标函数：必须自建打分器

没有度量就只能靠手感调提示词（BypassAIGC 和 thesis-optimizer 都卡死在这）。

## 5.1 可直接计算的指标（不需要任何模型）

| 指标 | 对应检测维度 |
|---|---|
| 句长标准差 / 变异系数 | burstiness |
| 句长分布形状（是否过度集中） | 句式均匀度 |
| 实词/虚词比 | 信息密度 |
| **数字密度、专名密度、单位密度** | **具体性（杠杆 1 的直接度量）** |
| 类符形符比 TTR | 词汇丰富度 |
| n-gram 自相似度 | 模板化程度 |
| 词性 n-gram 分布熵 | 句式多样性 |
| 特征词表命中密度（分级加权） | 表层标记 |
| 句式模式正则命中率 | 否定排比 / 三段式 / -ing 尾巴 |

## 5.2 本地小模型算困惑度 ⭐
跑一个小的中文语言模型（Qwen2.5-0.5B 之类）算逐句困惑度和困惑度方差。
**这是最接近第一类检测器真实视角的信号**，而且完全本地、免费、快。
三个前人方案没有一个做了这件事。

## 5.3 自建二分类器 —— 真正的目标函数 ⭐⭐

数据集构造方法（这个很关键，而且可行）：
- **人类正样本**：2022 年 11 月以前的中文学位论文 / 期刊摘要与正文段落。
  时间早于 ChatGPT 公开 = **保证是人写的**（维基指南提供的这个判据在这里派上大用场）
- **AI 负样本**：拿同样的标题 / 主题，用各主流模型生成同题段落
- 微调一个中文 BERT 做二分类

得到自己的检测器之后：
- 有了**可量化、可迭代**的目标函数
- 可以做 **best-of-N**：生成 N 个改写候选，打分选最优（质量跃升，没人做）
- 可以量化评估每条规则的实际贡献，砍掉无效规则
- 可以作为产品能力直接对用户输出

# 六、架构

```
输入文档
   ↓
① 解析：文档树（章→节→段→句）+ 术语白名单抽取
   ↓
② 逐句诊断打分：规则 + 统计 + 困惑度 + 自建分类器
   → 全文热力图 + 逐句归因 + 风险排序
   ↓
③ 定向选择：只处理高分句子，低分句子原样保留  ← 关键，见第七节
   ↓
④ 交互：空泛且不可自动补的句子 → 问作者要真实信息
   ↓
⑤ 改写：代码优先 → 必要时 LLM（best-of-N）→ 代码后处理
   ↓
⑥ 重新打分 → 未达标回炉（限轮次）+ 语义保真校验
   ↓
输出：改写结果 + 对照报告（改了什么、为什么改）
```

# 七、几个反直觉但重要的结论

## 1. 改得越少越好
**作者原本自己写的句子，本来就是人类文本，是最好的资产。**
每把一句话送进 LLM，就给它注入一次 AI 统计特征。

BypassAIGC 把全文无差别过两遍模型——对那些本来就是人写的段落，
这是**主动加害**。

所以"最小干预"不只是学术诚信原则（thesis-optimizer 是这么框的），
**它在统计上就是最优策略**。而做到定向干预的前提，正是先有逐句诊断。

## 2. 一致性是敌人，不是朋友
BypassAIGC 刻意维持全文用词和风格一致。但**一致性正是分类器度量的东西**。
人写长文时前后风格本来就会漂移。我们应该允许甚至制造这种漂移。

## 3. "降 AI 率"和"说人话"在最强的那个杠杆上是同一件事
杠杆 1（信息注入）同时提高困惑度、提高信息密度、让文章真的更好读。
所以产品不必在"对抗检测"和"提升质量"之间选边——
**沿着质量方向走，恰好就是最鲁棒的降 AI 路径**。
这既是技术判断，也解决了合规定位问题。

## 4. 不要碰无效指标
维基指南明确列出：语法完美、文风平淡、文风花哨、孤立的过渡词、
无引用——都**不能**判定 AI。所以：
**不要故意制造错别字、不要故意搞坏语法、不要换生僻词。**
市面上很多工具正是这么干的，纯属无效功，还破坏可读性。

# 八、实施顺序

1. **诊断引擎（规则 + 统计层）** —— 先做这个。它是后面一切的目标函数，
   而且本身就能做成免费引流的产品（"告诉你哪句像 AI、为什么"）
2. **本地困惑度模块** —— 接一个小模型，成本低，信号强
3. **代码改写层** —— 词表替换、删填充、拆合句、格式清理。不用 LLM，快且可控
4. **自建分类器** —— 有了它才能量化迭代和做 best-of-N
5. **LLM 改写层 + best-of-N** —— 处理需要语义理解的部分
6. **交互式具体化** —— 护城河，但需要产品设计打磨
7. **验证闭环**
