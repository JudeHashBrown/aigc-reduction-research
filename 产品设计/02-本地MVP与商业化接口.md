# 本地 MVP 与商业化接口

## 当前交付

本地 MVP 验证一条最小但完整的工作流：

```text
导入学生自己的正文
→ 31 项上下文检查
→ 查看具体问题与事实锚点
→ 安全清理 / 保真改写
→ 守卫验证
→ 前后对照并导出
```

它借鉴 Pangram 的“输入—分段分析—继续操作”和 Phrasly 的
“检测—改写—复查”操作节奏，但不复制未经校准的 AI 百分比，也不承诺通过某个
第三方检测器。

默认版本使用一个固定的本地 demo 账户和 SQLite 额度账本。可选的 `TRIAL_MODE=1` 为可信局域网试用者自动签发匿名会话，同时保留 CSRF 与独立账户/额度/任务所有权。分析和安全清理完全在运行服务的 Mac 上执行；只有用户主动配置并点击模型改写时，正文才会发往相应模型服务商。

当前“购买”是界面上明确标注的 `mock` 模拟支付：它只用于验证套餐、权益、订单幂等和额度扣退，不连接 Stripe 或易支付，不会产生任何真实扣款。
内测模式下完全禁用 mock 充值，每个新浏览器账户幂等获得总计 3,000 字的测试额度。局域网访问只绑定明确配置的私有 IP，并对 HTTP Host/Origin 做完全一致校验，不支持公网暴露。

## 当前 API 边界

| 接口 | 作用 | 将来是否可直接保留 |
|---|---|---|
| `POST /api/v1/analyze` | 31 项检查、定位、事实锚点 | 是 |
| `POST /api/v1/autofix` | 确定性安全清理 | 是 |
| `POST /api/v1/rewrite-jobs` | 创建异步保真改写任务 | 是，需换持久队列 |
| `GET /api/job/{id}` | 查询任务进度和候选结果 | 是，需增加用户隔离 |
| DOCX / PDF 接口 | 文档提取与导出 | 是，需接对象存储 |
| `GET /api/billing/plans` | 读取服务端产品表 | 是，生产改为后台配置 |
| `GET /api/billing/summary` | 当前套餐、可用额度和单次上限 | 是，必须绑定登录用户 |
| `GET /api/billing/ledger` | 本地额度变动记录 | 是，必须做所有权校验 |
| `POST /api/billing/checkout` | 当前只做 mock 模拟下单 | 否，需换成支付适配器 |
| `GET /api/session` | 查询内测会话与 CSRF | 否，正式版换生产认证 |

旧版无版本号的诊断/安全清理接口只作本地兼容，不应成为新客户端的依赖；旧 `/api/rewrite` 已返回 `410 Gone`，避免绕过新版守卫。

DOCX 导出的“保格式”是尽量保留对应段落和 run 样式，不是对任意 Word 结构的无损承诺。含复杂修订、域、文本框、脚注或手动换行的文档上线前必须扩充往返测试。

## 套餐假设与扣费契约

首版采用“免费分析 + 字数包 + 月卡”的混合模式，而不是只做订阅。低频用户可一次性购买，高频用户才为可预测的月度收入付费。

| 产品 ID | 展示名 | 中文人民币价 | 英文美元价 | 改写额度 | 单次上限 | 有效期/周期 |
|---|---|---:|---:|---:|---:|---:|
| `free` | 免费体验 | ¥0 | $0 | 800 计费额度 | 800 计费单位 | 不过期 |
| `pack_3k` | 小字数包 | ¥9.90 | $1.90 | 3,000 计费额度 | 3,000 计费单位 | 90 天 |
| `pack_10k` | 论文包 | ¥29.90 | $5.90 | 10,000 计费额度 | 10,000 计费单位 | 90 天 |
| `pack_30k` | 大论文包 | ¥69.90 | $12.90 | 30,000 计费额度 | 30,000 计费单位 | 90 天 |
| `student_month` | 学生月卡 | ¥39.90 | $7.90 | 20,000 计费额度 | 10,000 计费单位 | 30 天 |
| `pro_month` | 高频月卡 | ¥79.90 | $14.90 | 60,000 计费额度 | 60,000 计费单位 | 30 天 |

美元价为固定独立报价，不按实时汇率换算；订单、收银台、退款和后台收款统计以实际币种为准。当前报价仍需结合每个任务的 LLM `input_tokens` / `output_tokens`、模型实际单价、重试率、零采纳率、支付通道费率与退款持续计算贡献毛利；数据不足时不宜承诺“无限改写”。

统一计量契约：

- 分析与确定性安全清理免费，只有 LLM 保真改写扣额度。
- 当前计量版本为 v2：归一化后每个中文汉字计 1 单位，连续的英文字母或数字计 1 个单词；单词内撇号不断词，连字符分词，空格和标点不计费；中英混排合计。其他可见字符仍逐字符计量。
- 保留原文长度的独立安全上限；计费单位上限不等于可上传的原始字符长度上限。
- 保守/平衡按 1.0 倍，深度按 1.5 倍并向上取整。
- 既有余额数字与历史订单、任务、账本不重算；旧记录保留 v1（非空白字符）标识，新任务和新订单标记 v2，避免历史口径被误读。
- 任务创建时先在一个事务中预占全额；失败或零候选采纳全额释放，至少一个候选被守卫采纳则按整次预占量提交结算。
- 预占、结算和释放都以任务 ID 幂等，消费到期时间最近的额度桶，不允许并发超扣。

## 商业化时替换或增强的模块

核心编辑引擎不需要因收费重写。上线前在 HTTP 层增加以下适配器：

1. `IdentityProvider`：邮箱、验证码或第三方登录，所有订单、任务和文档必须强制绑定用户。
2. `EntitlementService`：将当前本地服务端套餐扩展为可审计配置，控制字数、候选数、批量与 API 权限。
3. `UsageLedger`：保留当前 grant/reservation/allocation/ledger 契约，生产迁移 PostgreSQL，增加对账、退款和客服调整流程。
4. `PaymentProvider`：将 mock 换成 Stripe 或某一家明确的易支付供应商，不让编辑引擎感知支付 SDK。
5. `JobStore`：把当前内存任务换成 Redis/数据库队列，支持断点、重试、租约和过期。
6. `DocumentStore`：加密对象存储、自动过期、用户主动删除和审计日志。
7. `CalibrationRepository`：只在用户明确同意后保存匿名特征和第三方检测结果。

支付回调必须经过签名校验并用支付平台事件 ID 做幂等；套餐判断由服务端执行，不能只靠前端隐藏按钮。

## Stripe 与易支付的接入顺序

### Stripe

- 字数包用 Checkout `mode=payment`，月卡用 `mode=subscription`；产品与 Price ID 只保存在服务端。
- 浏览器成功跳转只展示结果，不发额度。服务端必须使用原始请求体和 `Stripe-Signature` 验证 Webhook，校验金额、币种、产品和已付状态后才发放。
- 订阅额度只随 `invoice.paid` 等已确认付款事件发放；同一 Stripe event ID 只能处理一次。用 Customer Portal 管理换卡、取消和发票历史。
- 用 Test mode / test clocks 先覆盖成功、失败、延迟、重复/乱序回调、续费和取消。
- Stripe 当前的[Global availability](https://stripe.com/global) 页面未将中国大陆列为可直接开通的商户主体地区。选用 Stripe 前需确认支持地区的合法经营主体、KYC、税务、结算和目标客群的合规性；不能只因技术上能调 API 就上线。

### 易支付

“易支付”不是单一标准协议，不同供应商的签名字段、算法、重试规则和订阅能力不同。必须先确定具体供应商和官方文档，再写独立适配器。通用底线是：

- 本系统先生成唯一订单号，订单金额只来自服务端产品表；
- 同步跳转不发额度，只有验签成功的异步通知可将订单从 `pending` 变为 `paid`；
- 同时校验平台订单号、本地订单号、金额、币种/支付类型和交易状态，通知重试必须幂等；
- 如果通道没有可靠的自动续费，首版“月卡”应是一次性购买的 30 天额度，不宣传为自动订阅。

## 生产收款的强制门槛

本地服务只绑定回环地址，无法接收支付平台的公网 Webhook；固定 demo 账户也无法区分付款人。因此以下项目齐备前不得切换真实密钥：

- 有登录、会话保护、账号所有权校验和管理员最小权限；
- 有 HTTPS 公网回调端点，密钥进密钥管理器，日志不记录完整请求体、密钥或论文正文；
- 先保存未修改的原始回调字节再验签，支付事件有唯一约束，订单状态迁移与额度发放在同一数据库事务内；
- 完成对账、退款/争议、订阅取消、数据删除和隐私条款流程，并有支付测试环境的自动化回归。

## 推荐的收费边界

免费层保留完整的问题解释和事实安全能力，因为这是产品建立信任的部分。付费层可以
提供：

- 更长文本和更多并发任务；
- 平衡/深度多候选及更强模型；
- 历史版本、章节项目和云端续写；
- DOCX 批量处理、团队空间和 API；
- 用户授权后的第三方结果记录与个性化校准。

不建议把“为什么被提示”和事实守卫做成付费墙，也不按“保证降到某个百分比”收费。
对外定位应是“作者自有文本的表达编辑、可读性提升与事实保护”，不宣传“规避、绕过或保证通过 AI 检测”。第三方检测器分数只能是经过版本、学科和长度分层校准的参考指标，不是产品效果保证。

## 上线前门槛

- 用不同学科、不同长度、不同第三方检测器做盲测，分开报告结果；
- 建立隐私政策、数据保留期、删除机制和模型供应商披露；
- 对 LLM 故障、重复任务、超时与支付回调做集成测试；
- 使用真实 usage 和通道费率做套餐毛利、极端用量与退款压力测试；
- 保留 `licenses/Humanizer-zh-MIT.txt` 与第三方声明；
- 明确平台只优化用户已有内容，不生成虚假数据、引用、实验或经历。
