# 黑盒探测脚手架

**目的：把"哪条规则真的能让检测器分数降下来、降多少"测出来，而不是猜。**

五份参考资料给的阈值和权重全部无出处。照抄它们做出来的引擎，效果只能靠运气。
这套脚手架用单特征消融实验，测出每个特征对真实检测器的**因果效应量**。

---

## 为什么消融必须用代码，不能用 LLM

LLM 改写一次会同时改动句长、用词、语序、结构等多个变量，测出的分数变化
无法归因到任何单一特征。**五个参考项目都不知道自己哪条规则真正有用，根源就在这里。**

`ablations.py` 里的每个函数都是确定性正则变换，只动一种特征。

---

## 纯度检查

每个变体生成后，引擎会重新诊断，比对基准与变体的规则命中：

```
纯度 = 目标降幅 / (目标降幅 + 真实附带改动)
```

**关键细节**：删掉一整句时，句中顺带消失的其他命中不算附带损伤——那是同一次干预的
必然结果。只有落在**未编辑区域**的意外增减才计入。纯度 <0.6 的变体不参与归因，
`build.py` 会单独列出来。

---

## 操作流程

### 1. 准备基准文本

```bash
export LLM_BASE_URL=... LLM_API_KEY=... LLM_MODEL=...
python3 probe/gen_bases.py
```

生成 8 篇覆盖不同学科的 AI 学术段落到 `probe/bases/`。

**基准必须是 AI 文本**：探针测的是「消除某个特征能让检测器分数降多少」，
基准得先被判成高 AI 才有下降空间。真人论文放进去，检测器给 5%、消融完还是 5%，
任何规则的效应量都是 0——测不出东西，不是规则没用。

**基准必须与 `samples/` 严格分离**。原来的 `b01_医学影像.txt` 与
`samples/ai_sample.txt` 是同一个文件（MD5 都是 `81cd0686…`）。引擎照着那篇调出来，
再拿它测效应量等于自测自考。`tests/test_invariants.py::test_probe_bases_disjoint_from_dev`
现在会挡住这种污染。

**生成时不给任何风格指令**，只给题目——照抄 lieflat 的对照实验设计。
加了「要自然」「别像 AI」之类的要求，测到的就是我们自己的提示词，
不是模型的默认倾向。

### 1b. 这批基准已经推翻了两条自己的规则

跑完 8 篇新基准（4391 字）立刻暴露两个问题，都是开发样本掩盖掉的：

| | 开发样本（我手写） | 真实 AI 输出 | 人类对照 |
|---|---|---|---|
| 特征密度 | **4.45 / 百字** | **1.28 / 百字** | 0.20 / 百字 |

开发样本的 AI 特征密度是真实 AI 输出的 **3.5 倍**——那些「20→0」的成绩
是在人为加浓的文本上测出来的。剔除只报告的规则后，真实文本上是 **10 → 1**，
可处理的命中本来就只有 10 处。

- **S01 顿号罗列**：18 条命中里抽样复核，约 15 条是合法技术枚举
  （材料属性、法条项目、施工检查项、药理机制），误报率约 85%，已降为 low + 只报告。
- **L07 连接词**：段首形态实测 0.25/千字，与 lieflat 的 0.18 基本重合——
  这是目前唯一被两套独立语料交叉验证过的特征。但句中形态 3.98/千字
  （16 倍）的效应量**没人测过**，已拆成 L11 只报告。

### 2. 生成变体

```bash
python3 probe/build.py
```

每篇基准生成：`00_base` + 每个适用特征一个单消融变体 + `ZZ_ALL` 全清变体。
输出在 `probe/out/<基准名>/`，清单在 `probe/out/manifest.csv`。

### 3. 送检并记录

把每个 `.txt` 贴进检测器，把结果填进 `manifest.csv`：
- `detector` 列：检测器名（如 `朱雀`、`格子达`）
- `score` 列：检出的 AI 率数值

**建议顺序**：先测 `00_base` 和 `ZZ_ALL`。如果两者差距不大，
说明我们整套特征体系对这个检测器基本无效，后面的单变体就不用测了 —— 
这是最省事的早停判断。

**关于自动化**：本脚手架默认手工提交。若要脚本化，请先确认目标站点的服务条款，
并控制请求频率。不建议绕过验证码或频率限制。

### 4. 出效应量

```bash
python3 probe/analyze.py
```

输出每条规则的平均降幅、标准差、每处改动的效应，以及判定
（★强 / ✓有效 / ·弱 / ✗无效）。同时生成 `engine/weights.json`，
引擎加载后即用实测权重替换临时权重。

---

## 这个实验能回答的问题

1. **哪些规则值得做** —— 判定为「✗无效」的直接从引擎移除，别浪费改写预算
2. **改写优先级** —— 按「每处效应」排序，而不是按资料里的主观风险等级
3. **句长突发性到底管不管用** —— `BURST` 变体专门测这个。三份资料都说它是核心指标，
   但没有一份验证过中文检测器是否真的看它
4. **效果上界** —— `ZZ_ALL` 告诉你把所有已知特征清光最多能降多少。
   如果上界只有 10 分，那这条路走不通，得换思路

## 文件

| 文件 | 作用 |
|---|---|
| `ablations.py` | 16 种确定性单特征消融 |
| `build.py` | 生成变体 + 纯度检查 + 清单 |
| `analyze.py` | 效应量计算 + 生成 weights.json |
| `bases/` | 基准 AI 文本（自行放入） |
| `out/` | 生成的变体与 manifest.csv |
| `manifest_demo_模拟数据勿用.csv` | 管道验证用的**模拟**数据，不是实测结果 |


### 3. 按优先级提交（16 → 8 → 22）

46 次手工提交太多，而且大部分在第一层出结果前不值得做。`manifest.csv` 的
`priority` 列已经分好层：

| 层 | 次数 | 内容 | 为什么先做 |
|---|---|---|---|
| **P1** | 16 | 8 个 `00_base` + 8 个 `ZZ_ALL` | **决定性实验。** 全清都推不动分数，说明规则层这条路对该检测器无效，后面 30 次直接省掉 |
| **P2** | 8 | `BURST` 反向对照 | 预注册的证伪实验：lieflat 实测句长离散度人机无差异（CV 0.87×），**预测它没有效应**。测出显著效应反而说明学术文体与网文不同 |
| **P3** | 22 | 单特征消融 | 只在 P1 出现可测降幅后才做 |

先跑 P1。把 16 个文件逐个贴进检测器，分数填回 `score` 列，`detector` 列写检测器名。

**读 P1 的结果：**

- `ZZ_ALL` 比 `00_base` 低 **不到 5 个百分点** → 规则层对该检测器基本无效。
  别做 P3，把力气放到第二层改写和信息注入上。
- 低 **5–15 个百分点** → 有效但不够。做 P3 找出是哪几条规则在起作用。
- 低 **15 个百分点以上** → 规则层管用。做 P3 做完整标定，写进 `engine/weights.json`。

**两级靶子**：迭代用腾讯朱雀（免费，可以跑完整 46 次）；验收用知网／维普
（付费，只在关键节点花钱）。中国高校的守门人是知网（约 60%）和维普（约 25%），
不是 Pangram——对着 Pangram 调出来的东西在知网上未必适用。
