# 本地诊断界面

```bash
python3 web/server.py          # http://127.0.0.1:8765，自动开浏览器
python3 web/server.py 9000     # 换端口
```

**零依赖**——只用 Python 标准库（引擎侧需要 jieba 和 numpy，你已装好）。

> 你的环境设了 `http_proxy`。浏览器访问 `127.0.0.1` 一般会自动绕过代理；
> 若打不开，在浏览器代理设置里把 localhost 加入例外即可。

## 功能

| | 说明 |
|---|---|
| **诊断** | 逐句标注 + 点击看归因；中英文段落自动分别识别、各用各的规则 |
| **确定性修复** | 纯代码修复，毫秒级、可复现、不经模型 |
| **统计指标** | 中文侧与英文侧分别计算，未标定的阈值默认只记录不告警 |

## 中英文的处理差异（重要）

- **中文**：删词后句子通常仍通顺，因此套话、模糊归因、泛化结尾可以直接删除。
- **英文**：删掉动词或分词会把句子弄断，**而语法错误本身就是另一种可检测的异常**，
  比原来的 AI 味更糟。所以英文侧**只做替换**（`utilize`→`use`、`serves as`→`is`、
  `showcasing`→`showing`），只有句首过渡词等白名单词允许删除。
  没有安全改法的词宁可留着不动。

## 代码能修到哪，剩下的归谁

中英混排样本实测：**27 处特征 → 4 处，高风险 19 → 2，硬约束违反 5 → 0**。

剩下的 4 处都需要语义理解，代码不该硬碰：

```
[S03] Negative parallelism   「not just accurate, but also efficient…」
[S01] Rule of three          「efficient, scalable, and interpretable」
[P03] Challenges-and-future  「Despite these challenges」「future research will」
```

这条线就是**代码层与 LLM 层的分界**。再往前一步——把「效果显著」换成
「MAE 从 21.3 降到 19.8」——只能由作者提供，工具不应替他编造。

## 误报控制

同长度的人写对照文本：**检出 1 处，高风险段 0 个**。
只会报警的引擎没有价值，这个数字和 AI 稿的对比才是引擎可用性的依据。
